# 2026-09-09

The owner requested a runnable File-to-File MVP demonstration and visible
Rust-native parallel speed, and asked whether dependencies including Tokio were
declared in Cargo manifests. PM activated T-0071/S01 on
`feat/t-0071-parallel-mvp` after confirming Project WIP was zero and refining
Issue #47 with the exact allowlist, artifacts, Demo Command and non-claims.

The existing dependency set was already declared per crate and locked. Tokio is
not present. ADR-0023 retains scoped standard-library threads for the selected
local regular-file workload, where CPU formatting rather than async network
waiting is the parallel opportunity. No dependency or upstream source was added.

At source revision `6762f6c`, buffered CSV scanning and copy-free owned-record
formatting preserve the bounded ordered worker protocol. The deterministic
runner generates CSV/JSON workloads, checks every output byte identity, measures
1/4/8 workers and optionally invokes the checksum-pinned Embulk 0.11.5 executable.
Its strict validator rejects malformed or internally inconsistent reports.

The clean-revision evidence run passed and recorded quoted-CSV native scaling
from 77.0 MiB/s at one worker to 148.0 MiB/s at eight workers (1.92×), and JSON
to CSV from 49.2 to 64.1 MiB/s (1.30×). The selected native/reference ratios
were 2.32–4.44× and 1.77–2.30× respectively. JVM startup, fresh outputs and the
reference's one input task are included, so no general superiority follows.
Final-head acceptance, review, integration and canonical closeout remain.
